# R4 — Teacher workspace (v0.10.0)

The release that moves the teacher from the old `/admin` web tree to the deck's Teacher workspace
at `/teacher/*`. Every screen that exists today is rebuilt to `Quizzivy Teacher.dc.html`, the
backend gains what those screens draw and the server lacks, in-app notifications arrive for the
teacher and the student, and every legacy hashed join code is rotated (D5).

R4 runs after R2 (`72-r2.md`: permissions, ownership, the `/teacher/*` API rename, encrypted join
codes) and may swap with R3 (`73-r3.md`). It changes no permission rule and no API prefix. It
adds operations, each declaring an `x-permission` from `70-redesign-overview.md` §4.1 and each
added to R2's isolation suite in the PR that adds it, with an `x-resource` entry for every uuid
it takes in its path, query or body (T-R2.16).

**If R3 has not shipped** when R4 does (70 §2 rule 4), the student bell, the student Settings
items (T-R4.45) and T-R4.11's result line are built by R3 (`73-r3.md`), and T-R4.49 carries
R3's T-R3.1–T-R3.3 unchanged.

Modules the deck draws that ship later stay invisible here: Calendar and Attendance (R8),
Messages and Shared with me (R7), Courses and Vocabulary (R10), Gradebook and Reports (R9), the
Admin console (R5). No nav item, palette entry, menu item or button points at them (70 §2 rule 5).

**Deliverable:** the Teacher workspace from the deck, for every module that exists today, served
at `/teacher/*` inside the new `TeacherLayout`, with the backend it needs: profile and
preferences, signed-in devices, in-app notifications in both consoles, assignment review options
and per-student overrides, a grading queue, question level and skill, media rename and replace,
class schedule and room, dashboard figures and a version diff. Every legacy join code is rotated
at release, with an in-app notice to its teacher.

**Exit criteria:** every `/teacher/*` route matches the deck at 360, 768, 1024, 1280 and 1440, in
light and dark, with the sidebar expanded, collapsed and as a drawer (T-R4.51); the old teacher
tree is deleted and `router-chunks.test.ts` passes with its regexes updated, not weakened; no
active join code in production uses the legacy lookup; the five canaries are green and untouched;
every CI step of 70 §8 is green locally, including `pnpm e2e:live`; released as `v0.10.0`, and
Neon compute hours are measured for the week after (PR-7).

**Schema changes** (numbers assigned at merge; none indexes a populated table, so none is

**Decisions taken in this file, worth a second look.**

- **Time-based in-app notifications are materialised when the reader asks, not by a timer.**
  "Closes in 1 hour", "due tomorrow", "opened" and "result ready after close" are inserted
  idempotently by `GET /me/summary` and `GET /me/notifications`, at most once per five minutes per
  user. An in-app item only matters while its reader is in the app, and a background timer would
  wake Neon at every threshold of every assignment (the #134/#143 lesson). R7 adds the email
  channel, and with it the first in-API notification scheduler.
- **Submission notifications are one row per assignment per 15-minute bucket, upserted at submit
  time.** That is the deck's "Grouped every 15 minutes" without a flush job.
- **Legacy join codes are rotated by an idempotent job at API start-up, not by a manual
  command.** The API holds `JOIN_CODE_KEY` on every start, while an operator holds it only for
  R2's rekey procedure, supplied to `cmd/maintenance` from the offline copy (`operations.md`); a
  human step at release is one that can be forgotten; the job takes an advisory lock, audits
  each rotation as System and does nothing on its second run.
- **Extend is two operations.** Extending the window for everyone changes the assignment
  (`teaching.assignments.write`); extending or reopening for chosen students is an accommodation
  (`teaching.attempts.intervene`, the "Reset, void or extend attempts" row). We keep one
  requirement per operation here by choice, so the dialog picks the operation. Both recompute
  the deadline of attempts already in progress, which today keep the deadline they started with.
- **The Grading page finishes an attempt when its last manual answer is scored** (DG-64). Today a
  teacher must press "Finish grading" on the attempt page; the deck releases on the last score.
  The attempt page keeps its explicit button for re-grading.
- **Bulk actions reuse single-item operations through `BulkActions`**, which already confirms and
  reports partial failure. The exception is password reset: the single operation is rate-limited
  to five a minute per address (R2's `RateLimits()` entry, per actor from T-R4.53), so a
  class-sized reset would 429. It gets one bulk operation, capped at 40 students, hashing at
  most two at a time inside the global argon2 semaphore. It stays in the API rather than the
  worker: forty hashes take about ten seconds and the screen waits for the printable sheet.
- **The unpublished-changes banner comes from a diff, not from `updated_at`.** Publishing and
  "Make default" both bump `tests.updated_at` through its trigger, and a bank edit to a question
  the draft uses bumps nothing on `tests`. The diff that DG-66 needs anyway compares the draft
  with the latest version.
- **Media replace creates a new immutable asset** and re-points bank questions and draft-owned
  groups only (DG-09), and only those owned by the asset's owner. Published versions, and other
  owners' rows (bound through `scope.all` today, copies from R7), keep the old asset, which
  leaves the library but keeps serving them. `publish_snapshot_test.go` is the proof.
- **In the teacher workspace, content lists show the caller's own rows for everyone, admins
  included** (DG-53, the question R2 left to R4). Tests, bank, media, imports and assignments
  list only what the caller owns; `scope.all` still reads and edits any teacher's content by id
  and powers the Admin console's cross-teacher views. Students and Classes keep `scope.all`
  lists until R5's Admin Classes and Users take them over (T-R4.54, 70 §4.1).
- **Test cards show skills derived from their questions**, not a `tests.skills` column. Chips that
  are computed cannot drift from the content; the deck's removable chips are prototype state.
- **Nothing a teacher can do today disappears because the deck does not draw it.** The test card
  keeps a "…" menu (Duplicate, Archive, Delete); Classes keeps an Archived filter (the deck's own
  archive dialog promises "you can restore it any time"); "View results" on a student opens
  today's results sheet until R9's Gradebook; the API reference stays a Settings section for
  `system.api_reference` holders until R5 moves it to the Admin console.
- **Display time zone is per user; the server stays UTC.** The profile's time zone drives every
  date the web formats and every date the teacher types. "Today" on the dashboard and the 23:59
  expiry of a join code use the actor's zone, defaulting to `Asia/Ho_Chi_Minh`.
- **A new join code expires at 23:59 local on its last day**, as the deck draws ("24 Oct 2026,
  23:59"), rather than at the minute it was made N days earlier. A code that dies mid-lesson is
  worse than one that lasts the day.
- **Duplicate assignment has no Title field.** Assignments are named by their test; there is no
  assignment title to copy. The dialog keeps "Assign to".
- **The workspace switcher ships as a static label.** Its popover and the `workspace.admin` gate
  are built, but the "Admin console" row appears with the console in R5 (DG-53, rule 5).
