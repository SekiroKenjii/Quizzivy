# R6 — Question types and scoring (v0.12.0)

The deck draws question types the product does not have. The student engine asks students to
"Choose two" and counts words against a limit. The import screen offers True / False / Not
given. The builder has Matching, and grading scores essays on a band with rubric tiles. DG-60
names one canonical set and DG-61 an interim rubric model. After R6 the set is:

- single choice
- multiple choice, optionally "choose exactly N"
- true / false
- true / false / not given
- fill in the blank
- short answer, with an optional word limit
- essay, scored on a band
- matching
- cloze groups (question groups, unchanged)

`true_false` stays. Production holds it and the deck's question editor draws it, although
DG-60 leaves it out.

The work runs through every high-risk area in AGENTS: `questions`, `test_versions`, the
student projection, `attempts`, marking, grading, the engine and the importer. It is therefore
one vertical track, ordered schema → contract → bank → snapshot → projection → marking →
grading → result, with the screens after. Every server task on the track runs the five
canaries on its branch point and on its last commit:

- `server/internal/modules/tests/application/tests/publish_snapshot_test.go`
- `web/tests/units/media/audio-player.test.tsx`
- `server/internal/modules/attempts/application/tests/events_test.go`
- `web/tests/units/api/client.refresh.test.ts`
- `web/tests/integration/router-chunks.test.ts`

Every change is additive: new enum values, nullable columns and new tables. R6 therefore has
no contract step in R7. The release needs R4 (question `skill`, frozen on
`test_version_questions`) and R3's engine, with its unknown-type block. Branch
`work/redesign-r6` is cut from `develop`.

**Deliverable:** every type in the canonical set is authored in the editor, the builder and
question groups. Each is frozen at publish, delivered through a student-safe projection,
auto-marked or hand-graded (bands and rubric criteria for essays), shown on the result with
band, rubric, part and skill tiles, and mapped by the Word import where the deck says so.

**Exit criteria:**

- `publish_snapshot_test.go` and the other four canaries pass untouched.
- A new live spec takes a paper of every type from authoring to result.
- E2E 9 passes, extended to that paper and to the result-only keys.
- The migrations pass goose up/down/up and are rehearsed on a Neon branch.
- The engine's new types and the band result match the deck at the five widths.
- The release ships to production as `v0.12.0`.

**Decisions taken in this file, worth a second look.**

- **True / false / not given is its own type, stored as three fixed options and answered like
  a single choice.** `tfng` rows hold three `question_options` in fixed order (True, False, Not
  given) with exactly one correct. Students answer with the existing `choice` shape, and
  marking reuses the choice rule. The engine labels the options through `t()` by position, so
  vi shows Vietnamese whatever text is stored. Options are never shuffled. No new answer shape
  is needed, and an engine that predates R6 would at worst show the reload block.
- **"Choose exactly N" is `multiple_choice` with `selectCount`, marked per correct pick.** IELTS
  counts each letter of a "Choose TWO" item, so the question scores
  `points × correct picks ÷ N`. More than N picks scores 0; the engine prevents that, because
  the (N+1)th pick replaces the oldest. A plain multiple choice keeps its all-or-nothing rule,
  so existing questions do not change.
- **The word limit is advice, never truncation.** `maxWords` applies to short answers. The
  engine counts words live and flags "too many". The server stores whatever was typed, because
  autosave must never lose text, and the grader sees the over-limit badge and the deck's "Word
  limit exceeded" snippet. The penalty is the teacher's call.
- **An essay's band is converted to points, and the band is stored beside them.** Essays score
  3–9 in half steps, as the approved plan says. The deck's grading mock uses a nine-value set
  from 3 to 8, and the design team is asked to redraw it.
  - `manual_score = round(band × points ÷ 9, 2)`. An essay's default is 9 points, so points
    equal the band.
  - `final_score`, `finishGrading` and every points total are unchanged.
  - `AttemptScore.band` is the essays' points-weighted mean band, rounded to 0.5, and appears
    only when every scored question on the paper is a graded essay. A Writing Task 2 worth
    twice the points counts twice.
- **Rubric criteria are defined per question (DG-61, interim).** A question has up to six
  criteria, frozen at publish. When criteria exist, the band is their mean rounded half up to
  0.5: `floor(mean × 2 + 0.5) ÷ 2`, so 6.25 → 6.5 and 6.75 → 7.0. The editor offers an
  "IELTS Writing" preset of four localised labels. Without criteria, the teacher sets the band
  directly.
- **Band keys are the digit for a whole band and Shift+digit for the half above.** Thirteen
  values do not fit the deck's position keys 1…n. Digits 3–9 by `event.code` set that band,
  and Shift adds 0.5. Each button shows its hint. Points questions keep position keys.
- **Matching reuses `question_options` as its choice list and adds items.** The lettered
  choices are options, none of them marked correct. Each item is a row keyed to one choice by
  a composite FK `(question_id, correct_option_id)`, so a key cannot point into another
  question. The FK is `NO ACTION`: it is checked at the end of the statement, so a purge that
  cascades to options and items together passes, where `RESTRICT` would depend on the cascade
  order. Choices keep their order, because authors refer to letters. Marking is per item, like
  fill-in. The duplicate path copies items, and R7's copy-on-write reuses that path.
- **The student projection is written out in full (T-R6.5) and holds only rules and labels.**
  `selectCount` and `maxWords` are rules, like `caseSensitive`. Match items carry no key, and
  the rubric is not sent before submission. Correct matches, bands and criteria appear only
  on the result, behind the review policy.
- **Result tiles follow one rule, all behind `showScore`.** The first match wins:
  - a single essay with criteria shows its criteria
  - otherwise two or more parts show part tiles (R3)
  - otherwise two or more skills show skill tiles, from R4's frozen `skill`
  - otherwise there are no tiles

  The deck's Result variant 2 ("Unit 3 · Grammar check") draws topic tiles (Present perfect
  4/5, Past simple 4/5) on a one-part, one-skill paper. Topics have no model, so R6 does not
  build that variant: the paper shows no tiles (open item, and a DG entry through T-R6.15).

  When a paper's only hand-graded answer has a comment, the result shows it in the deck's
  comment callout, as the deck's Writing Task 1 does. Otherwise comments stay on their items.
- **True / false marking accepts the answer the engine actually sends.** The engine's `Choice`
  renderer (`take-test/components/QuestionBody.tsx`) answers true / false with
  `{type: "choice", optionIds: [id]}`, but `gradeTrueFalse` in `attempts/domain/grading.go`
  reads only `{value}`. As the code stands, every auto-marked true / false answered in the
  engine scores 0. R6's grader accepts both shapes. Past attempts are an open item, and a
  hotfix before R6 is recommended.
- **The Word import maps TFNG, "Choose N" and word limits, and nothing else.** Matching stays
  "Matching (not supported)", as the deck's import screen draws it. Essays are not recognised
  (open item).

## Open items

- **True / false answers already marked 0.** Found while writing this plan, and to be confirmed
  first with a failing test. The engine sends `choice` answers for true / false and the grader
  reads only `value`, so every true / false answered in the engine is auto-marked 0; the
  hotfix PR finds out since when from the history of both files. Recommendation: fix it now as a hotfix instead of waiting for T-R6.6, and have
  the hotfix PR count the affected answers and attempts. Thuong decides whether to re-mark
  them. Default: fix forward, report the count, no automatic re-mark.
- **DG-60.** The deck draws no authoring side for any new type. The editor panels ship
  extrapolated and need the design team's sign-off.
- **DG-61.** The rubric model (criteria per question, band = mean rounded to 0.5) is interim.
- **The deck's essay score set is 3–8 in nine values; R6 builds 3–9 in half steps.** A DG
  entry in `gaps.md` (T-R6.15) asks the design team to redraw the grading scale.
- **Topic tiles have no model.** The deck's Result variant 2 draws topic tiles on a one-part,
  one-skill grammar paper, and nothing in the data model defines a topic. The DG entry
  (T-R6.15) proposes an interim rule: tiles from question tags when a paper has one part and one
  skill. Thuong or the design team decides. Default: not built in R6; such a paper shows no
  tiles.
- **YES / NO / NOT GIVEN**, IELTS's opinion variant of TFNG, is not built. It would need a label
  set on `tfng`. Default: teachers use TFNG.
- **Essays in the Word import.** Writing prompts ("Write at least 150 words") are not
  recognised as essays. Default: the teacher changes the type in review.
