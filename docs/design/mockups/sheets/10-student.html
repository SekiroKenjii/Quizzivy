Student

Phone first, 390px, one-handed. The student’s whole product is four verbs: join, start, answer, see how I did. Everything below is measured against whether a fifteen-year-old on a bus with one bar of signal can do those four things without being told how.

1 · Getting in

§12 asks the join screens to look “calm and legitimate, not like a marketing page”. One card, one primary button, the class name as the largest thing on screen — because the only question the student has is am I joining the right class?

S-02 Login /login

Two paths on one screen, and the honest sentence at the bottom that prevents the single most common support message: “tôi không tạo được tài khoản”. The brand panel takes the left half on lg and up and is dropped below it — on a phone, half a screen of brand is half a screen the student cannot type into, so the card carries the wordmark itself there.

Why the password field comes first. Google is the majority path for students, but the admin logs in with a password every day and is the only person who can unblock anyone. Optimising the layout for the rarer user is correct here: the Google button is still one tap, unlabelled by rank.
No “forgot password”. v1 has no transactional email (§6.3), so a link that leads nowhere would be worse than its absence. The admin resets a password from the student detail page; the sentence at the bottom points there indirectly by naming who creates accounts.
Errors are one line under the button, never a toast: a toast that auto-dismisses on a failed login is a message the student never reads.

2 · Home — one obvious next action

§9 specifies three sections: Đến hạn / Sắp tới / Đã hoàn thành. On a phone, three equal lists is three decisions. So the nearest deadline is lifted out as a single card above them — the student’s next action is the first thing under their thumb, and the lists become reference rather than navigation.

“Sau khi nộp” is a permission list, not a feature list. Ticks and crosses in the same block, because a student who expects to see the correct answers and doesn’t will assume the app is broken. Reading it takes four seconds and removes a whole class of message to the teacher.
The integrity rule states the consequence, not the surveillance. “Bài sẽ được đánh dấu để giáo viên xem lại” — plus the reassurance that nothing is deducted automatically. §10.5 is explicit that these signals are evidence for a conversation; the copy must not imply a verdict.
The last line is the one students actually need. No pause. It sits under the button, not in the rules card, because that is where a hesitant thumb is already looking.
Fullscreen, when required, is entered by this button — browsers only grant it from a gesture (§10.2). If it is off for this assignment the rule simply does not appear; no greyed-out row.

3 · The engine

The one screen where a UI mistake costs a student marks. Rules it obeys: the answer is always the largest thing on screen; the timer is legible without being loud; the state of the save is never a mystery; and nothing — no dialog, no violation, no network failure — is allowed to swallow a tap that was meant for an answer.

Exit is always visible. §10.2 forbids trapping a student. “Thoát” is deliberately the least prominent control on the screen but it is never absent, and it never sits next to “Nộp bài”.
Save state lives in its own strip. It is the answer to “did my work survive?”, asked constantly and quietly. Putting it in the header would compete with the timer; putting it in a toast would make it disappear exactly when the student wants it.

S-07 Integrity — the two dialogs §10.2

These are the only non-dismissible dialogs in the product. They exist to make a consequence known while it can still be avoided. Neutral language, no alarm iconography, no shame — and the timer keeps running, which the dialog says out loud so the student does not discover it afterwards.

Duration, not just count. “trong 24 giây” comes straight from §10.1’s away-duration model. A 2-second notification never raises a dialog at all — minAwayMs is 3000.
The auto-submit cancel grants a final strike rather than resetting the counter, exactly as §10.2 specifies. The copy says what the button does, not what it protects against.
Fullscreen exit is not one of these dialogs. It gets an inline bar with “Quay lại toàn màn hình”, because Esc must always work and a modal over an exited fullscreen is a trap.

What the auto-submit cancel leads to. The final strike is exactly one because “Tôi vẫn đang làm bài” proves presence, not innocence: one more strike lets the student who alt-tabbed by accident finish, while a reset would turn the countdown into a free extend button. When that strike is spent, the end state names the cause in one sentence and stops — no countdown, no “vi phạm”, no alarm icon — because §10.4 makes the teacher the judge, so the screen must never pre-judge.

The footer is the only thing that gets tight. Between the 36px back button and two 8px gaps, “Danh sách câu” and “Câu sau” share 284px. Both keep their icon and label; the outline button is allowed to be the wider one, because a full label matters more than symmetry, and the row never wraps.

showScore: false is a real state, not an error. The student sees proof their work arrived, a timestamp they can quote, and a plain sentence about what is still hidden. Silence here generates the most support messages of any screen in the product.
S-09b Result — what each review flag withholds · loading · not ready · error /app/attempts/:id/result

Three review booleans give eight policy combinations (sixteen with the transcript flag), but each flag withholds exactly one block and leaves the others untouched, so the page is four subtractions rather than sixteen screens: showScore=false removes the score tile (drawn in S-09), showCorrectAnswers=false removes the “đáp án đúng” marking, showExplanations=false removes the explanation block, showTranscriptAfterSubmit=false removes the transcript under the player. A withheld block is never an empty gap — it is replaced by one muted sentence naming what the teacher chose not to show, so the student does not read the absence as a page that failed to load. The second row is the page’s own lifecycle, independent of policy: skeletons at the tile and card heights, a not-ready sentence for a paper released only after grading, and a load error that says the submission is safe before it asks for a retry.
