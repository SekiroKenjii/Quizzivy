Teacher · authoring

Desktop and tablet only, data-dense, ≥768px (§1.1). The measure for this half of the product is §1.2’s second goal: a test with mixed question types, including listening, authored in under fifteen minutes without reading documentation. Every decision on this sheet is in service of that sentence.

A-00 Navigation — built now for a size it does not have yet

Eight flat items work today. An LMS has thirty, and a flat list of thirty is a drawer nobody opens. Two cheap decisions taken now avoid a re-navigation later: group headings (Giảng dạy / Lớp học), which let a group be added rather than an item; and a command palette, which is how anyone who uses the product daily will actually navigate once there are more than a dozen destinations. A third: counts live in the nav, so “Chờ chấm 7” is visible from every screen without a dashboard visit.

“Chờ chấm” is a nav item, not a dashboard widget. It is the teacher’s inbox — the one queue that has to be emptied — and §8 currently reaches it only through /admin/attempts/:id from a monitor screen. Promoting it costs one route and removes the product’s most repeated navigation.
Sections earn their labels only above four items. Below that the headings are noise; the deck shows them because the LMS path (sheet 5) adds Nội dung, Lịch, and Báo cáo, and a heading appearing later would move every item the teacher has learned by position.
Collapsed at ≤1280px per §8, and the icons stay meaningful without labels — which is why every item has a lucide glyph that is not a generic document.

1 · Dashboard as a work queue

§8 lists five things: open assignments, attempts awaiting grading, active students, flagged attempts, recent attempts. Presented as five equal cards that is a report. Ordered by what needs a human it becomes a to-do list — and a teacher opening the app between classes has three minutes, not thirty.

Vietnamese search must be accent-insensitive. AGENTS.md records that pg_trgm is case-insensitive but not accent-insensitive — “nghe” must find “nghé”. That is a backend fact with a very visible frontend consequence: a teacher typing without diacritics on a laptop keyboard is the normal case, not the exception.
Results are typed and grouped, never a flat relevance list. A teacher searching “unit 5” is looking for either the test or the questions in it, and the group heading is what makes that distinction in a glance.
Actions come last. Search is the common case; commands are the power case. Putting commands first makes every casual search scroll.

Version is a column, not a page. §7’s invariant — an attempt references a testVersionId — is invisible until a teacher edits a published test and wonders what happened to the students mid-attempt. Showing v3 here is the cheapest possible explanation of a genuinely subtle model.
No delete. Only archive. A published test is referenced by assignments, attempts, and versions; a delete button that can fail on four different foreign keys should not be offered at all.
The audio badge counts. “4” listening questions is a scheduling fact — the teacher needs a quiet room and headphones — so it belongs on the row, not behind a click.
A-03a Tests list · archived tab /admin/tests?status=archived

Archive is the only “delete” a test gets (A-03), so the archived tab has to carry the way back. Khôi phục comes first and says what it does — the test returns as a draft, never straight to published, so nothing becomes visible to students by accident. Nhân bản stays available so an archived test can seed a new one without being restored; the same two-item menu appears on an archived row inside Tất cả.
